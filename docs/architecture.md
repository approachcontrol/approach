# Architecture

`approach` is a Go Bubble Tea TUI for managing git worktrees across repositories. User-facing behavior and key bindings are documented in `docs/tui-guide.md` (`README.md` is the short overview); session hooks and storage are `docs/agent-sessions.md`; config reference is `docs/config.md`; Flow phase semantics are `docs/flow-phases.md`.

## Package Map

- `cmd/approach/` — entrypoint. Handles `--version`, `session-hook --provider claude|codex`, and the `plan save|list|read|phase set` and `flow create|list|read|phase complete|phase block|phase needs-attention|phase restart|phase reset|phase set|phase add-child|plan set|issue set|pr set|merge set` subcommands (`plan.go`, `flow.go`). Subcommands resolve the artifact root without scanning repos or starting the TUI.
- `config/` — optional TOML from `$XDG_CONFIG_HOME/approach/config.toml` or `~/.config/approach/config.toml`. Missing config is non-fatal; unreadable files, malformed TOML, wrong types for known keys, and invalid known values are startup-fatal, while unknown sections/keys are ignored for version compatibility.
- `scanner/` — discovers repos under `WORKTREE_ROOT`, `[scan].root`, or `~/dev` (default depth 2, reducible via `[scan].max_depth`), excluding `*-worktrees`.
- `gitquery/` — read-only git queries. `parse.go` is pure parsing; `runner.go` defines the `Runner` seam wrapped by a `Querier` (`NewQuerier` injects a fake `Runner` for tests).
- `beadsquery/` — read-only Beads queries. Its injected `Runner` is the sole `bd` process-launch seam and owns `bd -C <absolute repo>`, the selected working directory, environment isolation, and bounded output. Ready delegates dependency-graph computation to `bd ready`; Blocked/Open/In-Progress use read-only uncapped status queries, while Closed bounds `bd list -s closed` to the newest 100 and independently reads the aggregate total from `bd stats --json --no-activity --readonly`. `Show` returns the raw human-readable output of `bd show <id> --readonly` without parsing or trimming. Pure captured-JSON parsers enforce required display fields; the stats parser accepts direct `summary.closed_issues` and the v1 envelope while rejecting missing, null, fractional, negative, wrong-type, or overflowing totals. Ready/Blocked/Open/In-Progress sort by priority then natural ID, while Closed requires RFC3339 `closed_at` and sorts newest-first with deterministic ID ties. The package marks only a missing executable or exact no-project/no-database diagnostics with `ErrNotConfigured`; the classification wrapper preserves the original runner cause, while all other runner and parser failures retain useful error detail.
- `actions/` — git mutations (worktree create/remove/prune/unlock, branch delete, stash drop, fetch `--prune`, pull `--ff-only`), clipboard, VS Code, editor commands, tmux/Zellij/terminal launches, and Codex/Claude launch/resume command construction with Approach hook metadata.
- `agent/` — supported agent command names (`codex`, `codex-app`, `claude`) with normalization and validation.
- `sessions/` — agent-session metadata and normalized transcripts under the user state dir; ingests Claude/Codex hook payloads. Blank or whitespace-only session IDs are rejected at ingest and in the store; session dirs are keyed by a hash of the provider session ID.
- `embeddedterm/` — runtime-only PTY process management for embedded CLI agents (sessions-mode resumes plus flows-mode phase and repair launches, both headless and interactive). It owns PTY start, output capture, live visible lines, input forwarding, resize, lifecycle state, and termination behind a small API so model tests can fake terminals. `StartCommandWithOptions` accepts an optional `OutputTransform` that rewrites child output before the emulator (used to render claude stream-json).
- `claudestream/` — renders the `claude --print --output-format stream-json --include-partial-messages` JSONL event stream into readable terminal lines (init header, thinking/tool-call/tool-result/text blocks streamed token-by-token, closing summary). It is a stateful, streaming `embeddedterm.OutputTransform` that renders from `stream_event` deltas and suppresses the duplicate aggregated `assistant` events (falling back to them if no deltas appear); non-JSON lines pass through verbatim so provider errors stay visible.
- `planstore/` — saved plans at `<root>/plans/<plan-id>/` (`meta.json` + `plan.md`).
- `flowstore/` — task-centric Flow records at `<root>/flows/<flow-id>/meta.json` with a seeded phase graph (plan → plan review → implementation → review loop → PR creation → autoreview → merge). The canonical transition table is `flowstore/transitions.go` (`AllowedNextPhaseStatuses`, `AgentSettablePhaseStatuses`); gating and readiness rules are in `docs/flow-phases.md`.
- `internal/artifacts/` — shared filesystem mechanics for the three stores: artifact-root resolution, absolute-root checks, `0700` dirs, `0600` atomic writes, safe IDs, phase-ID normalization (`NormalizePhaseID`), slugging, timestamp+slug collision allocation. Store-specific schemas, locking, and phase semantics stay in the owning store packages.
- `model/` — Bubble Tea state and key handling. Each list is a generic value-type `pane.Pane[T]` from `model/pane/`; prompt state is a typed `modal.Modal` from `model/modal/`; read-only views page through `less -R` via `actions.PageText` with stale-result protection. The runtime-only repos-pane collapse state expands content, keeps collapsed repos out of ordinary tab cycling, and preserves terminal-input pass-through; embedded PTYs span the full app width and are unaffected by collapse. Flow start orchestration is grouped behind `FlowStarter` in `model/flow_start.go`; expanded Flow phase rows can resume attached CLI provider sessions with fresh approach launch tracking (resuming a `completed`/`skipped` phase records the launch without reopening the phase, even if the launch fails); `codex-app` resume deep links are untracked app navigation because they cannot carry approach launch metadata. Sessions-mode CLI resumes and flows-mode CLI launches use one global runtime-only embedded-terminal list and active selection. The shared dock persists across every right-pane mode, `tab` cycles repo/list/terminal focus while it is expanded, and `ctrl+t` collapses or expands it outside terminal input (where `ctrl+] t` performs the toggle). Terminal command mode consistently owns switching, saved-session launch, detach, close, and quit; session/Flow scope remains slot lifecycle metadata rather than UI routing. In flows mode, `enter` on a selected launchable phase launches that phase; CLI providers run headlessly by default (`codex exec` / `claude --print`) and interactively when `h` toggles headless mode off; `codex-app` launches externally. AutoMode Flow advancement runs from an always-on, all-repos 1 Hz advance poll independent of the current view, and AutoMode CLI launches are always headless; `h` governs only manual launches. Headless claude streams `--output-format stream-json --include-partial-messages` rendered through `claudestream` (gated by `actions.UsesStreamJSONOutput`), so it runs directly rather than via the tmux transport and is not detachable. Embedded PTY startup failures and slot exhaustion mark the phase `needs_attention`. The production TUI starts in the flows pane (config default_view 8). The five git modes (ModeWorktrees…ModeReflog) and five contiguous Beads modes (Ready…Closed) are sticky grouped views. Keyboard `1` enters Git at its last-used subview, `2`–`4` select sessions/plans/flows, and `5` enters Beads at its last-used subview (Open before first use); `6`–`9` remain unbound. Group-scoped letters switch subviews, arrows wrap within either group, and ungrouped horizontal routing includes Beads after Flows. Each Beads mode owns independent pane/filter/cursor/scroll/availability/pending/request-token/error state. Closed sequences its bounded list before the aggregate count and accepts neither when either fails; the total is stored only after the same repo/mode/request-token checks as its rows. Same-repo switches and refreshes retain the target pane while the loading UI hides its rows, clears its prior error, and suppresses the Closed total; accepted success or not-configured results clear the target error, while accepted configured failures replace rows and totals with persistent detail. Repo changes invalidate and clear all repo-owned Beads rows, totals, selections, and errors while retaining each query, then fetch only the active mode. Acceptance checks repo, token, and active Beads mode before mutating any of that state. `enter` starts a detail request only for a visible settled filtered selection. Detail success and error delivery share one fence over repo, originating mode, active-view token, and current selected bead; repeated entry, mode/repo transitions, and list refreshes invalidate the token before the raw body can reach `actions.PageText`. The frozen `default_view` vocabulary spans `1`–`14`; Beads values `10`–`14` start and fetch the requested subview while seeding its sticky re-entry destination.
- `model/flow_repair.go` — the shared stalled-Flow classifier and isolated repair launcher. Repair permits only embedded `codex` or `claude`, reuses manual agent settings, and deliberately leaves the launch Flow-scoped but phase-untracked; launch/prefill/capacity failures therefore report status without regressing a phase.
- `ui/` — stateless lipgloss rendering from a `RenderParams` snapshot. It renders a four-column inactive repos strip with a restore hint and vertical selected-repo label when collapsed, assigning all released width to content. The right-pane header is a grouped selector: Git and Beads each add a letter-labelled second row beneath the top-level row. `GitContentOverhead` and `BeadsContentOverhead` remove that row from their list viewport so grouped panes keep the same outer height. The active Closed item uses the accepted pre-filter source-row count and total to render a plain count when complete or `<fetched> of <total>` only when truncated; loading and unavailable states omit it. The renderer includes Flow recovery labels (`recover-worktree`, `await-session`, `ended-session`, `session-mismatch`, `missing-session-id`, `missing-pr`), embedded terminal headers/live lines, sanitized Beads rows for all five modes, per-subview loading/empty messages, the calm `beads not configured` state, and persistent terminal-safe width-bounded Beads error detail. The embedded-terminal dock is a top-level, full-width pane between the pane row and the status bar: expanded state renders the framed terminal panel, and the collapsed and empty states reserve a one-row narrow-safe status chip (`no terminals running` when none are active). Pane and list heights subtract the dock rows via `EmbeddedTerminalDockRows` so the model and renderer stay in sync.
- `internal/version/` — version/commit/date injected via `-ldflags`.

## Invariants (load-bearing — do not break)

- Destructive actions are gated by destructive mode in the model; preserve that safety boundary. Locked worktrees are never deleted or pruned — unlock is a separate action. (See `docs/agent-operations.md` for how this shows up in practice.)
- Plan and Flow phase IDs are normalized (trimmed + lowercased) before matching, so case- or whitespace-variant IDs upsert the same logical phase, and updates collapse duplicate rows left by older records.
- All store roots must be absolute. `WORKTREE_ROOT` overrides `[scan].root`; `TERMINAL` overrides `[terminal].command` for launches outside tmux/Zellij. `[editor].command` is used for plans-pane Markdown editing and falls back to `EDITOR`; provider/launch config fields are parsed foundation only.
- Sessions, plans, and Flows share one artifact root (default `$XDG_STATE_HOME/approach/sessions/v1` or `~/.local/state/approach/sessions/v1`); moving or cleaning it moves saved artifacts too. TUI root precedence is `APPROACH_FLOW_STATE_ROOT` > `APPROACH_PLAN_STATE_ROOT` > `APPROACH_SESSION_STATE_ROOT` > `[sessions].root` > default; CLI subcommands also accept `--state-root` where documented. CLI-launched agents get the resolved root exported; `codex-app` receives prompt-only launch metadata plus copyable `--state-root` command examples.
- Branch lists hide non-root worktree branches; the root branch stays pinned at the top.
- Transcripts never live inside repositories — keep them under user state with restrictive permissions (see `docs/agent-sessions.md`).
- When a Flow is linked to a saved plan, transitioning a Flow phase to `completed` syncs a matching saved-plan phase with the same normalized phase ID to `completed`; missing plan phases are ignored, and sync failures mark the Flow phase `needs_attention`. Repeating `completed` for an already-completed Flow phase preserves that completed state even if the linked-plan sync later fails.
- Flow repair launches export the Flow ID and shared artifact root with an empty phase ID, never call `AddPhaseLaunchID`, and cannot attach a captured session to phase history. A Flow/launch-ID reservation fences duplicate and replayed repair messages, and a fresh persisted-Flow read revalidates eligibility before terminal allocation.

## Behavioral Notes

- Flow auto-advance is view-independent: a private unscoped advance poll detects live completion edges and launches the next AutoMode phase headlessly without changing focus or mode. A cleanly exited repair slot adds a one-shot marker fenced to the first successful unscoped poll generation that began after exit; the marker can re-arm the same non-merge drain after metadata-only repair or a running-to-ready reset. Retained repairs suppress ordinary completion-edge drains, and non-clean removal records a generation-fenced suppressing outcome that remains until a later state first exposes launchable work, so failure, termination, prefill failure, or a detached agent's delayed mutation cannot leak a deferred launch. The latest repair removal outcome is authoritative, allowing a clean retry to replace an earlier failure. A 3 s transient status announces auto-launches, `needs_attention`, and merge-ready transitions unless another status is active.
- Embedded terminals (sessions-mode resumes and flows-mode CLI launches) are runtime-only and not persisted or restored; quitting while any are running asks for confirmation before terminating them. Keep PTY mechanics in `embeddedterm`; model owns one global slot selection and dock state, unified `ctrl+]` command routing, picker/confirm state, session/Flow lifecycle metadata, and conversion from saved sessions to `actions.AgentCommand` contexts. `codex-app` session resumes and flow launches continue to use the external deep-link path.
- Keep ordinary Flow phase launch prompts minimal: state the action plus essential location metadata (worktree, branch, commit). Don't embed plan bodies, phase history, or status-update recipes unless the phase can't work without them. Repair prompts are the deliberate exception: they include the obstruction and structured recovery safety rules because the session is untracked and must leave persisted state honest.
